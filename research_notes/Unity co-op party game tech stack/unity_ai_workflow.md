# AI-Agent-Driven Unity Development and Verification Workflow (Windows 11, as of Sept 2026)

Scope: how an LLM coding agent (Claude Code etc.) working through files and the terminal can build and verify a Unity game with minimal hands-on editor use. Researched 2026-09-28. The Unity tooling for this changed a lot in mid-2026 (new standalone Unity CLI in July 2026, official MCP server, official agent plugin), so older guides that describe only `Unity.exe -batchmode` and the Hub `--headless` CLI are now incomplete.

## 1. Project structure conventions, and what can be created purely from files vs. what needs the editor

### Takeaway
Code (C#), assembly definitions, the package manifest and other text config can all be written straight to disk. Scenes, prefabs, ScriptableObject assets and materials should be *generated by Unity itself*, either by editor scripts run through `-executeMethod`/`unity run`, by Pipeline `[CliCommand]` commands, or by MCP tools, rather than by hand-writing the YAML. Unity's own agent skills deliberately "drive your open Unity Editor directly instead of hand-editing scene and asset files".

### Cited Findings
- `Packages/manifest.json` is plain JSON that the Package Manager reads when Unity loads a project. Dependencies map a package name to a registry version (`"com.unity.package": "1.0.0"`), a local folder (`file:<path>`), a tarball, or a Git URL (`https://repository/package.git#v1.2.3`). It also supports `scopedRegistries`, `testables` (packages whose tests load in the Test Framework), `enableLockFile` (default true, which gives deterministic resolution) and `resolutionStrategy`. — [Unity Manual: Project manifest](https://docs.unity3d.com/6000.3/Documentation/Manual/upm-manifestPrj.html)
- The manual only says the manifest is read "when Unity loads a project". It does not say whether edits are picked up while the editor is running. — [Unity Manual: Project manifest](https://docs.unity3d.com/6000.3/Documentation/Manual/upm-manifestPrj.html)
- Assembly definition (`.asmdef`) files split scripts into separately compiled assemblies. When dependencies are controlled, only changed assemblies need recompiling, which cuts compile time. — [Unity Manual: Assembly definitions](https://docs.unity3d.com/6000.3/Documentation/Manual/assembly-definition-files.html)
- Third-party Unity tooling is installed by adding a Git URL to the Package Manager, for example `https://github.com/CoplayDev/unity-mcp.git?path=/MCPForUnity#main`. The same string can go in manifest.json. — [CoplayDev/unity-mcp](https://github.com/CoplayDev/unity-mcp)
- Unity creates a `.meta` file for every file and folder under `Assets`. It stores the asset's unique ID (GUID) and its import settings. If a `.meta` is lost, references break: materials lose their textures, and GameObjects/prefabs get an "unassigned script" component. If you move or rename an asset outside Unity, you must move or rename its `.meta` to match. — [Unity Manual: Asset metadata](https://docs.unity3d.com/6000.3/Documentation/Manual/AssetMetadata.html)
- Unity's official agent skills repo says "Many skills drive your open Unity Editor directly instead of hand-editing scene and asset files", using the Unity CLI. — [Unity-Technologies/skills](https://github.com/Unity-Technologies/skills)
- The Unity Pipeline package exposes Editor operations covering "scenes, prefabs, materials, animation, lighting/NavMesh bakes, builds, screenshots, packages". Custom operations are C# functions tagged `[CliCommand]`. — [Unity Pipeline and Unity CLI technical walkthrough](https://unity.com/resources/unity-pipeline-cli-technical-walkthrough); [Unity search summary of Pipeline docs](https://docs.unity.com/en-us/unity-production-pipeline/local-tools-cli/unity-pipeline-package)

### Inferences
- **Safe to write directly as files:** C# scripts; `.asmdef`/`.asmref` JSON; `Packages/manifest.json`; shaders/HLSL; UXML/USS (UI Toolkit); JSON/CSV data files that game code reads at runtime; editor scripts under an `Editor/` folder or an Editor-only asmdef. Unity creates the `.meta` for a new file on the next import or refresh. The agent should **not** invent `.meta` files, except when a GUID must be stable before Unity sees the asset (prior knowledge, not checked this session).
- **Generate through Unity (editor script, `[CliCommand]`, or MCP):** scenes, prefabs, ScriptableObject instances, materials, animator controllers, Input Action assets, lighting/NavMesh bakes. The usual APIs (prior knowledge, not checked this session) are `AssetDatabase.CreateAsset`, `PrefabUtility.SaveAsPrefabAsset`, `EditorSceneManager.NewScene/SaveScene`, and `AssetDatabase.SaveAssets/Refresh`. Hand-editing scene/prefab YAML is possible with Force Text serialization, but fragile: it depends on fileIDs and on the script GUIDs from `.meta` files.
- **Suggested layout for this project:** `Assets/_Game/{Runtime,Editor,Tests/EditMode,Tests/PlayMode,Art,Prefabs,Scenes,Data}`, with one asmdef per layer: `Game.Runtime`, `Game.Editor` (Editor platform only), and `Game.Tests.EditMode`/`Game.Tests.PlayMode`. The tower "room/door/gimmick" definitions should live as data (ScriptableObjects or JSON) produced by editor-script generators. The agent can then add rooms by editing C#/JSON and re-running a generator command, rather than editing scenes.
- **Keep scenes thin:** a bootstrap scene plus prefabs built from code/data. That keeps most content diff-able, easy for agents to regenerate, and suits the randomized sub-level (1A/1B/1E...) design.

### Gaps
- No official source was found on whether the running Editor reliably picks up manifest.json edits without a restart. Community experience says it usually re-resolves when focus returns, but this was not verified.
- Detailed asmdef JSON field documentation (name, references, includePlatforms, defineConstraints) was not in the fetched excerpt.

## 2. Running Unity headlessly: batchmode, -executeMethod, tests, builds, screenshots, logs

### Takeaway
There are now two headless paths. (a) The classic `Unity.exe -batchmode -projectPath ... -executeMethod/-runTests -logFile -` cold-starts Unity for each call. (b) The **new Unity CLI** (`unity run | build | test | recompile | command | watch`, July 2026) wraps batchmode with structured JSON output and distinct exit codes. With the experimental `com.unity.pipeline` package it can also drive an already-open ("warm") Editor over a localhost HTTP API: enter Play mode, run tests, take screenshots, run `eval` C#. Screenshots need a real GPU and desktop session, so don't use `-nographics` for anything visual. A Windows 11 desktop with a GPU meets this requirement.

### Cited Findings
**Classic Unity.exe arguments**
- Automation arguments: `-batchmode` (no human interaction), `-quit`, `-projectPath <path>`, `-executeMethod <ClassName.MethodName>` (static method), `-logFile <path>` (use `-` for stdout), `-nographics`, `-buildTarget <name>`, `-accept-apiupdate`, `-ignorecompilererrors`, and licensing flags `-serial`, `-username`, `-password`, `-returnlicense`. — [Unity Manual: Editor command line arguments](https://docs.unity3d.com/6000.3/Documentation/Manual/EditorCommandLineArguments.html)
- If an exception is thrown during script execution, "Unity immediately exits with return code 1". Using `-quit` with asynchronous code "can cause the application to hang". — [Unity Manual: Editor command line arguments](https://docs.unity3d.com/6000.3/Documentation/Manual/EditorCommandLineArguments.html)
- `-nographics` "doesn't allow you to bake GI", because Enlighten realtime GI needs a GPU for the Meta Pass. — [Unity Manual: Editor command line arguments](https://docs.unity3d.com/6000.3/Documentation/Manual/EditorCommandLineArguments.html)
- Test Framework CLI: `-runTests`, `-testPlatform` (`EditMode`, `PlayMode`, or a BuildTarget such as `StandaloneWindows64`), `-testResults <path>`, `-testFilter` (semicolon list or regex), `-testCategory`, `-assemblyNames`, `-playerHeartbeatTimeout`, `-runSynchronously`. Use with `-batchmode`. Example: `Unity.exe -runTests -batchmode -projectPath PATH -testResults C:\temp\results.xml -testPlatform ...` — [Unity Test Framework: command line reference](https://docs.unity3d.com/Packages/com.unity.test-framework@1.4/manual/reference-command-line.html)

**New Unity CLI (standalone `unity` binary)**
- Released July 20, 2026. It is "a standalone unity binary for managing and interacting with editors, modules, projects, and auth from the terminal" and works with Unity 6.0 LTS and newer. The `com.unity.pipeline` package is "currently experimental". — [Unity blog: Meet the Unity CLI](https://unity.com/blog/meet-the-unity-cli)
- Commands: `run` (batch mode or a registered Editor command, `--log-file <path>`), `build` (`--list-targets`, `--list-profiles`, `--create-profile <target>`, `build run`), `test` (Edit Mode + Play Mode, writes an NUnit report), `recompile` (recompiles the running Editor's scripts and reports compile errors; `--strict` also fails on warnings), `watch` (e.g. `watch test` re-runs `unity test --affected` when files change). Output formats: `--format human|tsv|json|ndjson|github`. — [Unity CLI reference](https://docs.unity.com/en-us/unity-cli/unity-cli-reference)
- Exit codes: 0 success, 1 general error, 2 usage error, 3 auth failure, 4 configuration required, 6 primary operation failed, 7 Unity service or running Editor unreachable (retryable), 8 tests ran but some failed (`unity test` only), 130 SIGINT, 143 SIGTERM. — [Unity CLI reference](https://docs.unity.com/en-us/unity-cli/unity-cli-reference)
- `unity run /path/to/MyProject -- -executeMethod Builder.Build` launches batch mode automatically. Reserved flags (`-batchmode`, `-quit`, `-projectPath`) must not be forwarded after `--`, or the command fails with exit 6. `unity run <proj> --command my_command -- --count 3` runs a `[CliCommand]` (needs `com.unity.pipeline`). — [Unity-Technologies/skills: build-run-test.md](https://github.com/Unity-Technologies/skills/blob/main/skills/unity-cli/references/build-run-test.md)
- `unity test <proj> [--mode EditMode|PlayMode] [--filter 'NS.Tests'] [--coverage] [--shard 2/5] [--retries N] [--report-format junit|nunit,junit]`. Exit 8 means tests failed; exit 6 means the run never completed. — [Unity-Technologies/skills: build-run-test.md](https://github.com/Unity-Technologies/skills/blob/main/skills/unity-cli/references/build-run-test.md)
- `unity build <proj> --target <T> --execute-method Builder.PerformBuild` or `--profile 'Windows Release'` (Unity 6 build profiles). Desktop builds require `--output-path`. — [Unity-Technologies/skills: build-run-test.md](https://github.com/Unity-Technologies/skills/blob/main/skills/unity-cli/references/build-run-test.md)
- The Pipeline package "runs inside the Editor and auto-starts a local server when the Editor loads", speaking HTTP+JSON on localhost. Built-in commands include `unity command editor_play`, `unity command run_tests`, `unity command list_build_targets`, and `unity command screenshot`. Running `unity command` with no arguments lists what the connected Editor exposes. `eval` runs arbitrary C# in the live instance, is gated by a security token, and should be treated "like remote code execution". Unity's own description of the agent loop: an agent builds or changes something, runs a deterministic command to exercise it, "takes a screenshot, and checks the image". — [Unity Pipeline/CLI technical walkthrough](https://unity.com/resources/unity-pipeline-cli-technical-walkthrough); [Unity blog: Meet the Unity CLI](https://unity.com/blog/meet-the-unity-cli)
- Install the Pipeline package with `unity pipeline install`. Because the Editor stays open, scenes and the asset database stay "warm" in memory. The package can also drive a dev Player build and supports live code hot-reload in development builds. It is localhost-only and disabled by default in production. — [Unity Pipeline package docs (search summary)](https://docs.unity.com/en-us/unity-production-pipeline/local-tools-cli/unity-pipeline-package); [Unity blog: Meet the Unity CLI](https://unity.com/blog/meet-the-unity-cli)

**Screenshots**
- In batchmode on servers with no desktop session, users report black images. `-batchmode` does not fully disable graphics. The approach that works is to give a camera a `targetTexture` RenderTexture, call `Camera.Render()`, then `ReadPixels()`, or to use `ScreenCapture.CaptureScreenshot`. One forum reply says the machine needs both a GPU and "a full desktop session". This is a community answer, not Unity staff. — [Unity Discussions: Capture screenshots in batchmode](https://discussions.unity.com/t/capture-screenshots-in-batchmode/754535)
- `ScreenCapture.CaptureScreenshotIntoRenderTexture` plus `AsyncGPUReadback` avoids stalling the main thread. Capture after `WaitForEndOfFrame`. — [Unity Scripting API: CaptureScreenshotIntoRenderTexture](https://docs.unity3d.com/ScriptReference/ScreenCapture.CaptureScreenshotIntoRenderTexture.html)

**Logs**
- Windows log paths: Editor `%LOCALAPPDATA%\Unity\Editor\Editor.log`; Package Manager `%LOCALAPPDATA%\Unity\Editor\upm.log`; licensing `%LOCALAPPDATA%\Unity\Unity.Licensing.Client.log`; player `%USERPROFILE%\AppData\LocalLow\<CompanyName>\<ProductName>\Player.log`; crashes `%TMP%\Unity\Editor\Crashes`. — [Unity Manual: Log files](https://docs.unity3d.com/6000.3/Documentation/Manual/log-files.html)

### Inferences
- **For compile checks,** prefer `unity recompile --strict --format json` against a warm Editor. Falling back to a cold batchmode run means `-logFile -` (or a per-run log file) and grepping for `error CS\d+` / `Scripts have compiler errors`. A per-run `-logFile` is safer than reading the shared `%LOCALAPPDATA%\Unity\Editor\Editor.log`, which the interactive Editor overwrites.
- **Two modes, used together:** keep one warm Editor open with the Pipeline package and/or an MCP bridge for the fast inner loop (recompile, play, screenshot, console). Use cold `unity test`/`unity build` batchmode runs for the verification gate. Caution from prior knowledge, not checked this session: a second Unity instance generally can't open a project that is already open, so cold batchmode runs against the same folder need the Editor closed, or a separate clone/worktree.
- **Screenshot verification** on this Windows 11 desktop (GPU + logged-in session) should work in batchmode *without* `-nographics`, or via `unity command screenshot`. For player builds, the game can take a custom argument (e.g. `-autoshot <scene> <frames> <out.png>`) that loads a scene, waits N frames, calls `ScreenCapture.CaptureScreenshot`, then `Application.Quit()`. The agent can then read the PNG to check it. This is a design proposal, not a documented Unity feature.
- Prior knowledge, not checked this session: don't pass `-quit` together with `-runTests`, because the test runner exits by itself and `-quit` can end the run before results are written. `unity test` avoids this whole class of mistakes.

### Gaps
- It is not documented whether Pipeline commands (screenshot/eval) work in a pure `-batchmode` Editor or only in an interactive one. Unity's pages always say "running Editor".
- No official statement was found on the GPU/desktop-session requirement for batchmode rendering on Windows. The evidence is a community forum thread.
- The full list of built-in Pipeline commands was not published in the fetched pages. Running `unity command` against a live Editor lists them at runtime.

## 3. Unity MCP servers and AI integrations (2025–2026): capabilities and maturity

### Takeaway
There are three serious options. (1) **Unity's official stack:** the Unity MCP server inside the AI Assistant package (`com.unity.ai.assistant` 2.0 pre-release), the Unity CLI + Pipeline package, and an official Claude Code plugin (`unity@unity-agent-plugin`, beta). (2) **CoplayDev "MCP for Unity"**: MIT, about 14.6k stars, v10.0.0 (June 2026), Unity 2021.3–6.x. (3) **IvanMurzak "Unity-MCP / AI Game Developer"**: free, editor and runtime tools, screenshot and test tools. All need a live, open Editor, and none of them is a "1.0 GA" product from Unity yet.

### Cited Findings
**Official Unity**
- The Unity MCP server lives in the AI Assistant package. Docs are for `com.unity.ai.assistant@2.0` (2.0.0-pre.1). Architecture: AI client → relay binary (`~/.unity/relay/`, runs as the MCP server process) → Unity Editor hosting an MCP Bridge with a `McpToolRegistry`. The bridge starts automatically with the Editor and uses named pipes on Windows. Custom tools can be registered "using attributes, interfaces, or runtime APIs". AI Gateway connections are auto-approved; direct connections need user approval in Project Settings. — [Unity MCP overview (AI Assistant 2.0 docs)](https://docs.unity3d.com/Packages/com.unity.ai.assistant@2.0/manual/unity-mcp-overview.html)
- Blog post, May 11, 2026: official MCP supports Claude Code/Cursor and others. Built-in tools cover scene management, script editing, console access, GameObject inspection and build settings. It requires Unity 6 (6000.0)+. Setup is: verify the Unity Bridge is running, auto-configure the client, approve the connection. It is labeled open beta: features "may change, be limited, or be discontinued without notice". — [Unity blog: Unity AI MCP how to get started](https://unity.com/blog/unity-ai-mcp-how-to-get-started)
- **Conflicting pricing info.** Unity's "What is Unity AI" page (July 28, 2026) says the MCP server and AI Gateway (bring Claude/Codex/Gemini into the Editor using your own provider subscription) are included with Pro, Enterprise and Industry. Personal users get a 14-day trial with 1,000 credits that converts to a $10/month Personal subscription unless cancelled. — [Unity: What are Unity's AI tools?](https://unity.com/resources/what-is-unity-ai). The May blog instead says an "active trial or subscription to Unity's AI tools beta" is required ([Unity blog](https://unity.com/blog/unity-ai-mcp-how-to-get-started)), and a search-engine summary claimed the MCP server "is free... will not consume Unity credits" ([search result, unverified](https://unity.com/features/ai)). The Personal-tier MCP entitlement is therefore unclear.
- Official Claude Code plugin: `/plugin marketplace add Unity-Technologies/unity-agent-plugin` then `/plugin install unity@unity-agent-plugin`. It needs Unity 6+. The Unity CLI is optional but recommended, and the agent can install it. It bundles skills (UI, rendering fixes, IAP, ads, localization, level-design tools, render-pipeline reviews) under `/unity:` slash commands. Status: beta (0.1.6-beta noted for Codex). — [Unity-Technologies/unity-agent-plugin](https://github.com/Unity-Technologies/unity-agent-plugin)
- The Unity Skills repo works with Claude Code, Copilot, Cursor, Cline and 50+ agents. Claude Code users are told to install the plugin instead. — [Unity-Technologies/skills](https://github.com/Unity-Technologies/skills)

**CoplayDev / MCP for Unity (community, MIT, not affiliated with Unity)**
- 48 tools in 10 groups covering scene/GameObject management, script editing, assets/prefabs/materials, testing, and optional animation/VFX/UI/ProBuilder groups. Also 25 read-only resources, stdio or HTTP transport, and multi-instance routing (several Editors in one MCP session). Requires Unity 2021.3 LTS → 6.x and Python 3.10+ via `uv`. Install from the Git URL, then Window → MCP for Unity → Configure All Detected Clients. — [MCP for Unity docs](https://coplaydev.github.io/unity-mcp/); [CoplayDev/unity-mcp](https://github.com/CoplayDev/unity-mcp)
- v10.0.0 released June 30, 2026. About 14.6k stars and 1.5k forks. Active beta branch. — [CoplayDev/unity-mcp](https://github.com/CoplayDev/unity-mcp)

**IvanMurzak / Unity-MCP ("AI Game Developer")**
- 52 tools, 48 prompts, 1 resource across 12 categories: Assets, GameObject, Scene, Editor, Script, Package, Object, Reflection, **Screenshot**, **Console**, **Tests**, Type. Any C# method can become a tool with one attribute line. Works in the compiled game at runtime (`UnityMcpPluginRuntime`). Stdio or streamable HTTP, Docker option, built-in configurators for 14 clients including Claude Code. Free. — [IvanMurzak/Unity-MCP](https://github.com/IvanMurzak/Unity-MCP); [LobeHub listing](https://lobehub.com/mcp/ivanmurzak-unity-mcp)

### Inferences
- **For this project:** use the Unity CLI + Pipeline package (free, official, scriptable exit codes, screenshots/eval) as the main agent interface, and add **one** MCP bridge for richer scene/GameObject inspection. CoplayDev is the most mature and widely used free option. IvanMurzak's is useful if runtime (in-build) inspection of bots/netcode matters. Unity's official MCP is attractive but may cost $10/month on Personal. Its beta status and pricing should be checked before relying on it.
- MCP bridges and Pipeline commands all run inside the Editor process, so every script change still triggers a recompile and domain reload. The agent's loop should always be: write code → recompile and read errors → then act.

### Gaps
- No independent reliability benchmarks or post-mortems of these MCP servers on large projects were found.
- The exact tool names of the official Unity MCP were not listed in the fetched docs.

## 4. Licensing/activation for CLI use, and installing Hub/Editor/modules from the command line

### Takeaway
A **Personal license cannot be activated with serial/command-line flags**. It is activated by signing in, through Unity Hub or probably the new `unity auth login` / `unity license`. After that the machine holds a license file (`C:\ProgramData\Unity\Unity_lic.ulf`) that batchmode runs can use, which is how GameCI runs Personal licenses in CI. Installation is fully scriptable: `winget install Unity.CLI` (or `winget install -e --id Unity.UnityHub`), then `unity install <version> -m <modules>`. The Hub `--headless` CLI is deprecated as of Hub 3.18.0. The Editor takes roughly 8.5 GB on disk for Unity 6.x.

### Cited Findings
- "The following procedures don't apply to Unity Personal. To activate a license for Unity Personal, log in to the Unity Hub. To return a Personal license, log out of the Unity Hub." Serial activation (`-quit -batchmode -serial SB-XXXX... -username ... -password ...`) is for Plus/Pro only. Manual `.alf`/`-createManualActivationFile` activation also does not work for Personal. — [Unity Manual 6000.4: Manage your license through the command line](https://docs.unity3d.com/6000.4/Documentation/Manual/ManagingYourUnityLicense.html); [Unity Manual: Manual activation (Windows)](https://docs.unity3d.com/6000.1/Documentation/Manual/ManualActivationCmdWin.html)
- GameCI's Personal-license CI recipe: install Hub, sign in, "Get a free personal license", then take the generated file at `C:\ProgramData\Unity\Unity_lic.ulf` (Windows) and supply it with email/password as secrets. A `.ulf` may not exist even when Hub shows a license, so activation must actually complete. Licenses aren't tied to a Unity version or platform. — [GameCI: Activation](https://game.ci/docs/github/activation/)
- The Unity CLI has a `license` command that "Lists, activates, and returns Unity licenses on this machine", `unity auth login` (browser sign-in), `unity auth status`, and service-account auth through `UNITY_SERVICE_ACCOUNT_ID`/`UNITY_SERVICE_ACCOUNT_SECRET` env vars for build agents. — [Unity CLI reference](https://docs.unity.com/en-us/unity-cli/unity-cli-reference); [Use the Unity CLI](https://docs.unity.com/en-us/unity-cli/use-unity-cli)
- Install the CLI with `winget install Unity.CLI` (update: `winget upgrade Unity.CLI`). Unity Hub now installs it automatically. — [Use the Unity CLI](https://docs.unity.com/en-us/unity-cli/use-unity-cli); [Unity CLI intro](https://docs.unity.com/en-us/unity-cli/unity-cli)
- Editor install commands: `unity install lts`, `unity install 6000.3.7f1`, `unity install 6000.3.7f1 -c <changeset>`, `unity install lts -m ios android webgl`, `--cm` for child modules (e.g. Android SDK/NDK). Add modules later with `unity install-modules -e <ver> -m <ids>`; list them with `-l`. Show installed Editors with `unity editors -i`, register an existing install with `unity editors add "C:\Program Files\Unity\6000.3.7f1"`, set the default with `unity editors default <ver>`. Version aliases: `latest`, `lts`, `6`, `6.5`. — [Unity CLI reference](https://docs.unity.com/en-us/unity-cli/unity-cli-reference)
- The Hub CLI is deprecated as of Hub 3.18.0. The old syntax on Windows was `"C:\Program Files\Unity Hub\Unity Hub.exe" -- --headless install -v <ver>` / `install-modules`, with module IDs such as `windows-il2cpp` and `android`. — [Unity Docs: Hub CLI](https://docs.unity.com/en-us/hub/hub-cli); [Unity Hub CLI usage](https://docs.unity.com/en-us/hub/use-hub-cli)
- Known Hub CLI limitation: modules can only be added to Editors that were installed through the Hub. — [Unity Issue Tracker](https://issuetracker.unity3d.com/issues/installing-modules-for-an-editor-version-in-the-headless-mode-fails-when-the-editor-version-is-not-installed-through-the-hub)
- Hub winget ID: `winget install -e --id Unity.UnityHub`. — [winstall: Unity.UnityHub](https://winstall.app/apps/Unity.UnityHub)
- Disk size: the Unity 6.5 raw engine is about 8.5 GB on Windows without templates, IDE or docs; Unity 6.2 on macOS about 8.49 GB. These figures come from forum threads, not official specs. — [Unity Discussions: Editor disk size growth](https://discussions.unity.com/t/unity-editor-disk-size-growth-through-the-years/1723987); [Unity Discussions: Optimise installation](https://discussions.unity.com/t/unity-hub-feature-request-optimise-installation-of-editor/1690858)
- Unity AI tools and Unity CLI/Pipeline need Unity 6.0+. CoplayDev MCP also supports 2021.3+. — [Unity blog: Meet the Unity CLI](https://unity.com/blog/meet-the-unity-cli); [Unity: What is Unity AI](https://unity.com/resources/what-is-unity-ai)

### Inferences
- **Practical setup on this Windows 11 box:**
  1. `winget install -e --id Unity.UnityHub` (brings the Unity CLI), or `winget install Unity.CLI` alone.
  2. The user signs in **once** (a human step: browser sign-in via Hub or `unity auth login`) and activates the free Personal license. The agent must not enter credentials.
  3. `unity install 6000.3.xf1 -m windows-il2cpp` (IL2CPP optional; Mono is enough for development builds). Add `webgl` only if a web build is wanted.
  4. `unity pipeline install` inside the project. After that the agent can run everything unattended.
- Budget roughly 10–15 GB for Editor + modules + one project `Library` folder. This is an estimate: 8.5 GB Editor per the forums, plus Library, which grows with assets.
- Batchmode with a Personal license should work once the `.ulf` exists on the same machine, as GameCI demonstrates. Plan for an occasional re-sign-in if the entitlement expires.

### Gaps
- No doc was found confirming that `unity license activate` can activate a **Personal** entitlement, rather than only serial/floating licenses.
- No official download-size figure (compressed installer vs. installed) for Unity 6.3/6.5 Windows + IL2CPP was found.
- The exact module ID list was not retrieved. `unity install-modules -e <ver> -l` prints it.

## 5. Pitfalls: domain reload, import times, Library, .meta/GUIDs, version control, Git LFS

### Takeaway
Most of the slowness and fragility for agents comes from: recompiles plus domain reloads on every script change (reduce with asmdefs and by disabling domain reload on entering Play mode); the first import that builds `Library/` (never commit it, and expect a long first open); `.meta`/GUID drift when files are created, moved or deleted outside Unity; and binary art bloating Git (use LFS). Add a strict agent rule set to handle these.

### Cited Findings
- Domain reload is time-consuming and slows iteration. You can turn it off for entering Play mode (Project Settings → Editor → Enter Play Mode Options), but static fields and static event handlers then persist between Play sessions and must be reset manually. A domain reload still happens on every asset-database refresh that detects script changes. Unity recommends leaving domain reload off, partly to prepare for the move to CoreCLR, which has no domain reload. — [Unity Manual: Enter Play mode with domain reload disabled](https://docs.unity3d.com/6000.3/Documentation/Manual/domain-reloading.html); [Unity Manual 6000.6: Configuring how Unity enters Play mode](https://docs.unity3d.com/6000.6/Documentation/Manual/configurable-enter-play-mode.html)
- asmdefs limit recompilation to the assemblies that changed. — [Unity Manual: Assembly definitions](https://docs.unity3d.com/6000.3/Documentation/Manual/assembly-definition-files.html)
- Unity's standard `.gitignore` excludes `[Ll]ibrary/`, `[Tt]emp/`, `[Oo]bj/`, `[Bb]uild/`, `[Bb]uilds/`, `[Ll]ogs/`, `[Uu]ser[Ss]ettings/`, `[Mm]emoryCaptures/`, `[Rr]ecordings/`, `.vs/`, `*.csproj`, `*.sln`, `*.suo`, `*.unitypackage`, `*.apk/*.aab`, `mono_crash.*`, `sysinfo.txt`, and `Assets/StreamingAssets/aa*`. — [github/gitignore: Unity.gitignore](https://github.com/github/gitignore/blob/main/Unity.gitignore)
- Missing or unsynced `.meta` files break references: textures drop off materials, and scripts become "unassigned" on prefabs. Moves and renames outside Unity must carry the `.meta` along. — [Unity Manual: Asset metadata](https://docs.unity3d.com/6000.3/Documentation/Manual/AssetMetadata.html)
- `unity watch test` re-runs affected tests when files change. `unity recompile` reports compile errors from the running Editor. Exit code 7 means the Editor is unreachable, for example mid domain reload, and is marked retryable. — [Unity CLI reference](https://docs.unity.com/en-us/unity-cli/unity-cli-reference)
- The Pipeline `eval` command is effectively remote code execution. Keep it local and token-gated. — [Unity Pipeline/CLI technical walkthrough](https://unity.com/resources/unity-pipeline-cli-technical-walkthrough)

### Inferences
- **Agent rules** (synthesis from the sources above plus standard Unity practice; items marked "prior knowledge" were not checked this session):
  1. Commit every `.meta` with its asset. Never delete or rename assets with plain `mv`/`rm` while Unity is closed unless the `.meta` goes with them. Prefer `AssetDatabase.MoveAsset/DeleteAsset` through a command or MCP.
  2. Keep Asset Serialization = Force Text and Version Control = Visible Meta Files (prior knowledge; these are Unity 6 defaults), so scene/prefab diffs are readable.
  3. Put binary art/audio (`*.fbx, *.png, *.psd, *.wav, *.ogg, *.exr, *.tga`) in Git LFS through `.gitattributes`. Consider Unity YAML merge (`UnityYAMLMerge`) as the merge tool for scenes/prefabs (prior knowledge).
  4. Expect the **first open or import** of a fresh clone to take minutes, because `Library/` is rebuilt from scratch. Never commit or delete `Library/` casually. Keep one long-lived warm Editor so agents don't pay this cost repeatedly.
  5. Treat exit code 7 or "Editor busy" as "wait for the domain reload, then retry". After writing C#, always run `recompile` and wait for zero errors before Play, tests or screenshots.
  6. With domain reload disabled, reset static state with `[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)]` in game code (prior knowledge). This especially matters for singletons in bot/AI and networking managers.
  7. Split asmdefs by volatility, e.g. `Game.Core`, `Game.Tower`, `Game.Bots`, `Game.Net`, `Game.UI`, `Game.Editor`, and tests. Frequent agent edits then recompile only a small assembly.
- **Proposed end-to-end agent workflow (synthesis):**
  1. **Setup (once, human-assisted):** install Hub/CLI with winget; the user signs in and activates Personal; `unity install <6000.x LTS>`; create the project (`unity open` on a template, or a batchmode create); `git init` with Unity.gitignore plus LFS `.gitattributes`; `unity pipeline install`; optionally add the CoplayDev MCP Git URL to `manifest.json`; install the Unity Claude Code plugin.
  2. **Inner loop (warm Editor):** the agent edits C#/JSON → `unity recompile --strict --format json` → fix errors → `unity run --command Generate<Thing>` (a `[CliCommand]` editor generator for rooms/prefabs/SOs) → `unity command editor_play` → `unity command screenshot` → the agent reads the PNG and the console (via MCP `read_console` or the log) → repeat.
  3. **Verification gate (cold, deterministic):** `unity test <proj> --mode EditMode` and `--mode PlayMode --report-format junit` (fail on exit 8) → `unity build <proj> --profile "Windows Dev" --output-path Builds/Win` → launch the player with a custom `-autoshot` / `-bots 8 -seed N -runSeconds 60` argument that writes screenshots and a JSON telemetry summary, then quits → the agent checks images and telemetry. Automated 8-bot runs can smoke-test the co-op/betrayal loop.
  4. **Human checkpoints:** feel and fun testing, visual polish review, and anything licensing- or store-related.

### Gaps
