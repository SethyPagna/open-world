# Anchor the party game on Unity 6.3 LTS

The best 2026 stack for a small AI-assisted team building a stylized 1-8 player co-op/betrayal game with bots is **Unity 6.3 LTS with URP 17, host-authoritative client-server netcode over Steam, CC0 art libraries layered with procedural animation, and the new Unity CLI as the agent's main way of controlling the Editor**. Unity 6.3 is the only current LTS (supported to December 2027). Unity has frozen HDRP feature work and tells new projects to use URP. The recent Unity hits in this genre (Lethal Company, PEAK, R.E.P.O., Content Warning, Liar's Bar) were built by teams of one to seven people and shipped on cheap host- or relay-based sessions, not dedicated servers. For netcode, default to **Netcode for GameObjects (NGO) 2.x in host mode over the community Facepunch Steam transport**. That is what Lethal Company shipped on, and Steam lists no per-player fee for it. Before committing, run a two-week physics proof of concept against FishNet. Rule out Distributed Authority entirely, because hidden roles need one trusted authority. Agent tooling changed a lot in mid-2026. A standalone `unity` CLI (July 2026), an experimental Pipeline package that lets an agent drive an already-running Editor, an official Claude Code plugin and a Unity MCP server that is now free together make near-headless development realistic, but every one of these pieces is beta or experimental. Only one setup step needs a human: signing in to activate the free Personal license. The biggest risks are not rendering or engine limits. They are a forced NGO 3.0 migration when the project moves to Unity 6.7 LTS, keeping physics in sync with 8 players, and asset licenses with clauses about AI that an AI-driven team has to read carefully.

## Unity 6.3 LTS buys 14 months before one planned upgrade

**Unity 6.3 LTS shipped on 4 December 2025 as the first LTS since 6.0, with support through 4 December 2027** ([Unity blog](https://unity.com/blog/unity-6-3-lts-is-now-available)). The latest patch is 6000.3.25f1 ([endoflife.date](https://endoflife.date/unity)). The alternatives are worse. Unity 6.0 LTS went GA on 17 October 2024 and **loses support on 16 October 2026**, a few weeks from now ([Unity news](https://unity.com/news/unity-6-will-release-globally-october-17-2024-unity-announces-at-annual-unite-developer-conference); [endoflife.date](https://endoflife.date/unity)). Unity 6.6 (31 August 2026) is an "update" release. Update releases are production-ready but supported only until the next one ships, so choosing 6.6 puts the team on a treadmill of upgrades ([Unity 6 support](https://unity.com/releases/unity-6/support)). Unity 6.7 LTS is in beta as 6000.7.0b1 and is expected late in 2026, but no firm date was found. A single secondary blog claims the release after it, "Unity 7", will be 6.8 in Q1 2027 ([makaka.org](https://makaka.org/unity-tutorials/best-version)), and that claim is unverified. The new agent tooling (Unity CLI, Pipeline, official MCP) needs Unity 6.0 or newer ([Unity blog](https://unity.com/blog/meet-the-unity-cli)), so any Unity 6 LTS qualifies.

The upgrade to 6.7 LTS in 2027 is predictable, and it comes with a netcode migration. **NGO 3.0.0 (changelog dated 14 September 2026) requires Unity 6000.7.0b1+ and takes a hard dependency on Netcode for Entities 7.0.0**, which also brings in Entities, Burst and Collections. It renames assemblies and namespaces and turns previously obsolete APIs into compile errors. NGO 2.x keeps receiving fixes for Unity 6.6 and older ([Unity Discussions](https://discussions.unity.com/t/netcode-for-gameobjects-3-0-0-is-now-available/1736792); [NGO changelog](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@3.0/changelog/CHANGELOG.html)). The migration is mostly mechanical renaming, the kind of bulk edit an agent does well. Schedule it as a named milestone after 6.7 has received a few patches. FishNet and Mirror do not tie the netcode to the engine version, which is one real argument for them.

Licensing costs are now predictable. The runtime fee was cancelled in September 2024 ([Unity blog](https://unity.com/blog/unity-is-canceling-the-runtime-fee)). **Unity Personal stays free until revenue *plus funding* passes $200,000**, and the "Made with Unity" splash screen is optional on Unity 6 ([CG Channel](https://www.cgchannel.com/2024/09/unity-scraps-controversial-runtime-fee-but-raises-prices/)). Funding counts toward that limit, so a publisher advance or a grant can require Pro seats before the game earns anything. **Pro costs $2,310 per seat per year from 12 January 2026.** Unity Version Control's free tier covers unlimited seats and 25 GB. Havok Physics is no longer bundled with paid plans from 6.3 LTS and is now a paid add-on ([CG Channel](https://www.cgchannel.com/2025/11/price-of-paid-unity-subscriptions-to-rise-but-free-subs-extended/)). This stack doesn't use Havok.

## URP is the only pipeline still gaining features

Unity's 2026 render-pipeline strategy settles the pipeline choice. **HDRP now gets only Nintendo Switch 2 support and stability fixes.** Built-in RP is deprecated as of 6.5 and kept through 6.7 LTS. URP is gaining physical light units, auto exposure, a physical sky, real-time GI, SSR and on-tile post-processing. Unity's own advice is to "strongly encourage using URP when starting any new project" ([Unity](https://unity.com/topics/render-pipelines-strategy-for-2026)). URP 17 already has most of what used to justify HDRP. It has **Adaptive Probe Volumes with lighting-scenario blending, the GPU Resident Drawer, STP upscaling and a Render Graph framework** for custom passes ([Unity Manual](https://docs.unity3d.com/6000.0/Documentation/Manual/urp/whats-new/urp-whats-new.html)). Lethal Company's stylized HDRP look is a real precedent, but it was built on Unity 2022.3 before the freeze ([LethalSDK](https://github.com/HolographicWings/LethalSDK-Unity-Project)). One developer reported HDRP barely passing 30 FPS on Steam Deck ([Unity Discussions](https://discussions.unity.com/t/unity-hdrp-rendering-on-steam-deck/1495611)). That is a single report, but it points the same way as Unity's roadmap. The genre's handheld bar is achievable: PEAK became Steam Deck Verified in August 2025 through a patch, not at launch ([Pocket Tactics](https://www.pockettactics.com/peak/steam-deck-verified)).

One performance feature needs a correction. **The GPU Resident Drawer skips any object with an Animator or Animation component in its hierarchy.** It works only with Forward+ or Deferred+, needs compute shaders, and requires Enlighten realtime GI to be off ([Unity Docs](https://docs.unity.com/en-us/engine/6000.6/manual/analysis/graphics-performance-profiling/in-urp/reduce-draw-calls-urp/reduce-rendering-work-on-cpu/gpu-resident-drawer)). It will speed up the modular tower rooms but not the eight animated players and bots. Their draw cost has to be kept down with low-poly meshes and few materials. APV scenario blending suits betrayal gameplay directly: a sabotage "lights out" state can blend between baked lighting scenarios instead of switching on expensive realtime lights.

### A premium stylized look is a shader-and-post stack the agent can own

A premium look comes from art direction and post-processing more than from the pipeline. Cult of the Lamb, a Unity game, credits much of its look to lighting and custom solutions for its 2.5D setup ([Unity blog](https://unity.com/blog/games/recipe-behind-smash-hit-cult-of-the-lamb)). The recommended stack starts with **ramp or stepped toon lighting with soft shadow bands, plus a Fresnel rim light tinted per team or role**, which also helps readability in an 8-player crowd. Add outlines (inverted-hull on characters, or a depth/normal edge pass written as a Render Graph renderer feature), SSAO for contact grounding, then bloom, a color-grading LUT and a vignette. Unity's Toon Shader supports URP and offers outlines, rim light, shade steps and MatCap. It is under the **Unity Companion License, but every release, up to 0.15.0, is still labelled "-preview"** ([GitHub](https://github.com/unity-technologies/com.unity.toonshader); [releases](https://github.com/Unity-Technologies/com.unity.toonshader/releases)). For an AI-driven team, a small hand-written HLSL toon shader that the agent owns end to end is the better default. It is plain text, it diffs cleanly, and it avoids UTS's large parameter surface. Shader Graph and VFX Graph assets are serialized node graphs, which agents handle much less reliably than HLSL.

The "frog in a well" scale reveals (well, then sky, then space) run into a real URP gap. **Camera-relative rendering, which prevents float-precision z-fighting at large distances, is documented only for HDRP**, and forum users are still asking for it in URP ([HDRP docs](https://docs.unity3d.com/Packages/com.unity.render-pipelines.high-definition@17.0/manual/Camera-Relative-Rendering.html); [Unity Discussions](https://discussions.unity.com/t/urp-camera-relative-rendering-when/921267)). Build each layer near the world origin. Sell the sense of scale with nested skyboxes, background shell meshes, fog gradients and slow Cinemachine pull-backs. Use a floating origin wherever players actually travel far ([Wikipedia](https://en.wikipedia.org/wiki/Floating_origin)). No verified source was found on URP volumetric fog, so plan for faked light shafts such as additive cone meshes.

### Shuriken particles and code-first juice beat the heavier tools

**VFX Graph is still in preview for URP.** It needs compute shaders and SSBOs, and under URP it supports neither gamma color space nor OpenGL ES ([Unity docs](https://docs.unity3d.com/Packages/com.unity.visualeffectgraph@17.5/manual/System-Requirements.html)). Make the fully scriptable Particle System the default for dust, confetti, hit stars and door sparkles. Save VFX Graph for a few hero moments such as the sky-to-space transition, and test those on Steam Deck early. For game feel, **PrimeTween is allocation-free and has shake, punch and sequences built in**. It installs through a UPM scoped registry (`com.kyrylokuzyk.primetween`) ([GitHub](https://github.com/KyryloKuzyk/PrimeTween)). Its license is custom, not a standard open-source license: shipping it in a game is allowed, but redistributing the source is restricted ([license](https://api.github.com/repos/KyryloKuzyk/PrimeTween/license)). Feel offers 150+ ready-made feedbacks, including freeze-frame hitstop and Cinemachine Impulse ([Feel](https://feel.moremountains.com/)), but it is configured mostly in the inspector and its price was not verified. A ~200-line in-house feedback system on top of PrimeTween and Cinemachine 3 Impulse is easier for an agent to reason about. It can cover 50-120 ms hitstop, squash and stretch on jump and land, UI punches, and chromatic pulses on betrayal reveals.

The lettered sub-levels (1A, 1B, 1E…) should come from a **seeded, graph-based generator that picks from curated modular room prefabs** tagged by theme, size, puzzle and gimmick monster. Wave Function Collapse is slow even with threading and spreading work across frames ([PVS-Studio](https://pvs-studio.com/en/blog/posts/csharp/1027/)), so use it at most for dressing inside a room. A seed does three jobs at once: every client builds identical rooms from one replicated number, agents add rooms by editing data, and failed test runs can be replayed exactly.

Two lessons carry over. First, **physics synchronization is the recurring pain point**. Fall Guys needed a networking consultancy. Second, 8 players plus bots is above the genre norm. Gorilla Tag also shows that a Unity hit can run on cosmetics-only monetization with URP helping performance ([Unity blog](https://unity.com/blog/another-axiom-gorilla-tag)), which suits the planned skin shop.

### Hidden roles rule out Distributed Authority and Shared mode

In a betrayal game, role assignment, votes, sabotage outcomes and win checks must live in one place, and each role must be sent only to the player who owns it. **Unity's own docs say Distributed Authority usually has no single physics simulation, makes cheating easier for bad actors, and does not suit games that need accurate predictive motion** ([NGO docs](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/terms-concepts/distributed-authority.html)). Photon Fusion's Shared mode has the same problem, and Fusion's rigidbody prediction works only in Host or Server mode ([Photon](https://doc.photonengine.com/fusion/v2/addons/physics-addon-2.1)). The right model is host-authoritative client-server.

| Option (Sept 2026) | Physics / prediction | Steam path | Cost | License | Verdict |
|---|---|---|---|---|---|
| **NGO 2.x host mode** | Weakest prediction; Unity advises simulating physics on the server and syncing transforms | Facepunch transport | Free | Unity | **Default**: official, integrates with MPPM and Play Mode Scenarios |
| FishNet 4.7.3R | Built-in prediction and reconciliation | FishySteamworks, hides IPs ([docs](https://fish-networking.gitbook.io/docs/fishnet-building-blocks/transports/fishysteamworks)) | Free | Free for games; only competing netcode products are barred ([license](https://github.com/FirstGearGames/FishNet/blob/main/LICENSE.md)) | **Proof-of-concept challenger** ([releases](https://github.com/FirstGearGames/FishNet/releases)) |
| Mirror v96.11.3 | Snapshot interpolation; lag compensation still beta | FizzySteam (community) | Free | MIT; 200M+ players, 1,000+ Steam games | Safe, proven fallback ([releases](https://github.com/MirrorNetworking/Mirror/releases)) |
| Photon Fusion 2 host mode | Best out-of-box rigidbody prediction | Photon cloud | Free 100 CCU plan (one app); 500 CCU $125/mo; Premium $0.50/CCU, $1,000/mo minimum ([pricing](https://www.photonengine.com/fusion/pricing)) | Commercial | Only if physics prediction is worth a per-CCU bill |
| NGO Distributed Authority | No single physics simulation; cheat-prone | UGS | 6,000 connection-hours/mo free, then $0.001/hr ([UGS](https://unity.com/products/gaming-services/pricing)) | Unity | Reject for hidden roles |
| Photon PUN 2 | Little physics help | Photon cloud | CCU plans | Commercial | Maintenance mode; Photon recommends Fusion ([forum](https://forum.photonengine.com/discussion/19306/pun-2-or-fusion)) |

The cost difference matters if the game becomes a hit. **Steam Datagram Relay hides player IPs and handles NAT traversal over Valve's backbone.** It is available once a version of the game ships on Steam, and the partner page lists no price ([Steamworks](https://partner.steamgames.com/doc/features/multiplayer/steamdatagramrelay)). "Free" is therefore an inference from the missing fee, not a quoted term. Photon's Premium tier, by contrast, would bill on the order of $10,000 a month at 20,000 CCU ($0.50 × 20,000). That is a small fraction of the 200k+ peaks Content Warning and R.E.P.O. reached. Unity Relay is free for the first 50 average CCU, then $0.16 per additional average CCU plus bandwidth ([UGS pricing](https://unity.com/products/gaming-services/pricing)). It is needed only for non-Steam or cross-store builds, because a Steam transport cannot connect players across stores. Unity also **deprecated its own Multiplay game-server hosting on 1 April 2026** ([Unity status](https://status.unity.com/info_notices/362941)), which removes the easy dedicated-server path and reinforces host-based sessions.

Bots come from the topology, not from a library, because no netcode package ships a bot-seat framework. In a host-authoritative stack, **bots are host-owned NetworkObjects driven by host-side AI (NavMesh plus behavior or utility logic) and replicated exactly like players**. One person can then run an "8-player" match alone, and every test session exercises the player code path. The cost is that seven bots' AI plus prop physics all run on the host's CPU, so profile that case from week one. For physics comedy without syncing every bone, keep characters kinematic or controller-driven, simulate props on the server, and add a **cosmetic client-side active-ragdoll layer that is never networked**. Human: Fall Flat and PEAK-style slapstick then costs almost no bandwidth.

The netcode decision should be settled in a **1-2 week proof of concept on at most two candidates (NGO 2.x vs FishNet), run under 100-200 ms RTT with packet loss and jitter, sending inputs rather than results** ([dev.to](https://dev.to/gamedevtoollab/choosing-the-right-real-time-networking-stack-for-unity-in-2026-29f4)). Test the game's most physics-heavy verb (grabbing, carrying, being chained together). No first-party comparison of 8-player physics sync quality exists. The community benchmark repo compares throughput, not feel ([GitHub](https://github.com/StinkySteak/unity-netcode-benchmark)).

## CC0 libraries and procedural motion stand in for an art team

The hardest content for agents to produce is original sculpting, texture painting and keyframe animation. The pipeline should route around all three. Build **2-4 signature hero bodies (bean, frog, blob) as simple smooth-shaded Blender meshes**, by hand or with Blender Python the agent writes. Give them a minimal skeleton mapped to Unity Humanoid and fixed attach points for shop cosmetics. Pull base clips from CC0 libraries. **Quaternius's Universal Animation Library has 120+ CC0 clips**, but the free Standard tier is roughly 60-70% of the pack in FBX/glTF/OBJ, and the .blend sources are in the paid Source tier ([Quaternius](https://quaternius.com/packs/universalanimationlibrary.html)). **KayKit Character Animations now has 161 clips (150+ free), also CC0**, and asks users not to resell unmodified copies ([itch.io](https://kaylousberg.itch.io/kaykit-character-animations)). Mixamo clips are royalty-free for commercial games with no credit required, but the raw files may not be redistributed ([Adobe](https://helpx.adobe.com/creative-cloud/faq/mixamo-faq.html)). Humanoid retargeting onto stubby bean or frog proportions tends to look off, so the motion that makes the characters feel alive should be procedural. Unity's Animation Rigging package layers foot placement, hand IK, aiming and damped secondary motion on top of clips ([Unity docs](https://docs.unity3d.com/Packages/com.unity.animation.rigging@1.1/manual/index.html)). Custom constraints are C# jobs. UnitySpringIK, for example, is a Burst-compiled three-bone digitigrade leg solver for Unity 6000.0.23f1+ (license unchecked) ([GitHub](https://github.com/Garegni/UnitySpringIK)). Add spring bones on ears, antennae and hats, and PrimeTween squash and stretch on jumps and landings.

Audio follows the same logic. **Unity's built-in AudioSource and AudioMixer, driven by a code sound manager, are enough to start and are fully scriptable.** That covers pooled one-shots, randomized pitch, per-surface footsteps, snapshot ducking, and music layers crossfaded by game state. FMOD Studio is authored in a separate GUI, so adopt it only for adaptive music (tension rising as a betrayal vote nears) or if a human sound designer joins. Its free Indie tier requires under $200k yearly revenue. Wikipedia now gives the Indie budget cap as under $600k, not the $500k in 2020 articles. The tier also requires registering the project and **showing FMOD attribution in the game** ([Wikipedia](https://en.wikipedia.org/wiki/FMOD); [GameFromScratch](https://gamefromscratch.com/fmod-studio-now-free-for-indie-game-developers/)). Wwise's reported free tier below a $250k budget could not be checked against Audiokinetic's pricing page ([Audiokinetic](https://www.audiokinetic.com/en/wwise/pricing/for-games/)).

For this team, the AI clauses are the notable finding. Sonniss forbids using its sounds to train AI without permission. Synty's one-time-purchase EULA bans use in generative-AI programs and datasets. Coding agents that read and move asset files are not obviously "training" or a "generative AI program", but neither license was written with agentic pipelines in mind. **A human should read both before those assets enter an agent-driven repository.** Synty's subscription terms also fit poorly with a monetized cosmetics catalog, because edits to Synty assets become Synty's IP. Keep a machine-readable `licenses.csv` (file, source URL, license, attribution text), and add an editor validator that fails the build when an imported asset has no entry. No Unity terms on ownership of assets made by Unity's AI generators were found, so don't ship AI-generated art until they are checked.

## The July 2026 Unity CLI makes the Editor agent-drivable

The agent interface has four layers, all new and all pre-release. **The standalone Unity CLI (released 20 July 2026, still reporting version 1.0.0-beta.5) provides `run`, `build`, `test`, `recompile`, `command` and `watch`, with JSON/NDJSON/GitHub output and distinct exit codes** ([Unity blog](https://unity.com/blog/meet-the-unity-cli); [CLI reference](https://docs.unity.com/en-us/unity-cli/unity-cli-reference); [install docs](https://docs.unity.com/en-us/unity-cli/use-unity-cli)). The **experimental `com.unity.pipeline` package** starts a localhost HTTP server inside the running Editor. That lets the CLI enter Play mode, run tests, take screenshots, and call custom `[CliCommand]` C# operations while scenes and the asset database stay loaded in memory. Its `eval` command runs arbitrary C# behind a security token, and Unity likens it to giving an assistant access to your computer ([Unity walkthrough](https://unity.com/resources/unity-pipeline-cli-technical-walkthrough)). The **official Claude Code plugin** (`claude plugin marketplace add Unity-Technologies/unity-agent-plugin`, then `claude plugin install unity@unity-agent-plugin`) is beta 0.1.6 under the Unity Companion License. It bundles skills that drive the open Editor instead of hand-editing scene files ([GitHub](https://github.com/Unity-Technologies/unity-agent-plugin); [skills](https://github.com/Unity-Technologies/skills)). The fourth layer is an MCP bridge.

| MCP bridge | Status | Strength | Caveat |
|---|---|---|---|
| **CoplayDev MCP for Unity** | MIT, v10.0.0 (30 Jun 2026), ~14.6k stars, Unity 2021.3–6.x ([GitHub](https://github.com/CoplayDev/unity-mcp)) | ~47-48 tools incl. tests, optional animation/VFX/ProBuilder groups, multiple Editors in one session | Needs Python 3.10+ via `uv`; not affiliated with Unity |
| Official Unity MCP | AI Assistant 2.0.0-pre.1, open beta ([docs](https://docs.unity3d.com/Packages/com.unity.ai.assistant@2.0/manual/unity-mcp-overview.html)) | Now **free, no credits, no concurrency limits** per Unity's FAQ ([Unity AI](https://unity.com/features/ai)) | Needs the project linked to Unity Cloud; May 2026 blog said a trial or subscription was required ([blog](https://unity.com/blog/unity-ai-mcp-how-to-get-started)) |
| IvanMurzak Unity-MCP | Apache-2.0, 70+ tools ([GitHub](https://github.com/IvanMurzak/Unity-MCP)) | Also runs **inside a compiled build**, useful for inspecting bots and netcode live | Smaller community |

Use the CLI plus Pipeline as the backbone, because it has scriptable exit codes and a plain-batchmode fallback. Add exactly one MCP bridge for scene and GameObject inspection. CoplayDev is the most-adopted option and depends on no Unity AI entitlement. The official MCP is worth trying now that the FAQ calls it free, but the FAQ contradicts Unity's May blog, so confirm it in the Editor. Unity's own in-editor AI agent is a separate product: Personal users get a 14-day, 1,000-credit trial and then pay $10 a month ([Unity AI](https://unity.com/features/ai)).

### Agents write text; Unity generates assets

Unity gives every asset a `.meta` file holding its GUID. If a `.meta` is lost or falls out of sync, materials drop their textures and prefabs end up with unassigned scripts ([Unity Manual](https://docs.unity3d.com/6000.3/Documentation/Manual/AssetMetadata.html)). That determines the working rule. **Agents write C#, `.asmdef` files, `Packages/manifest.json`, HLSL, UXML/USS and JSON data directly. Scenes, prefabs, ScriptableObjects, materials and animator controllers are produced by Unity** through editor-script generators run as `[CliCommand]`s or MCP calls. Keep scenes thin (a bootstrap scene plus prefabs assembled from data), so most content stays diffable and regenerable. Split assemblies by how often they change (`Game.Core`, `Game.Tower`, `Game.Bots`, `Game.Net`, `Game.UI`, `Game.Editor`, tests), so a typical agent edit recompiles only one small assembly ([Unity Manual](https://docs.unity3d.com/6000.3/Documentation/Manual/assembly-definition-files.html)). Unity recommends turning off domain reload when entering Play mode, partly in preparation for CoreCLR. Its 6000.6 manual lists "Reload Scene only" as the default ([Unity Manual](https://docs.unity3d.com/6000.6/Documentation/Manual/configurable-enter-play-mode.html)). That means static fields in bot and network singletons carry over between Play sessions unless code resets them. Commit every `.meta` with its asset, move assets only through `AssetDatabase`, keep `Library/` out of Git ([Unity.gitignore](https://github.com/github/gitignore/blob/main/Unity.gitignore)), store binary art in Git LFS, and keep one long-lived warm Editor so agents don't pay for a fresh import repeatedly.

| Loop stage | Command | Pass signal |
|---|---|---|
| Compile | `unity recompile --strict --format json` | Exit 0; warnings fail under `--strict` |
| Generate content | `unity run <proj> --command GenerateRooms -- --seed 42` | Exit 0 |
| Look | `unity command editor_play` → `unity command screenshot` | Agent inspects the PNG and the console |
| Logic gate | `unity test <proj> --mode EditMode` | Exit 0 (8 = tests failed, 6 = run never finished) |
| Integration gate | `unity test <proj> --mode PlayMode --report-format junit` | Exit 0 |
| Build | `unity build <proj> --profile "Windows Dev" --output-path Builds/Win` | Exit 0 |
| Bot soak | Player launched with custom `-bots 8 -seed N -runSeconds 60` args | JSON telemetry shows no exceptions, desyncs or stuck win states |

Several details bite agents. **`unity run` fails immediately with exit 6 if any of five reserved flags (`-batchmode`, `-quit`, `-projectPath`, `-useHub`, `-hubIPC`) is passed through after `--`** ([Unity skills](https://github.com/Unity-Technologies/skills/blob/main/skills/unity-cli/references/build-run-test.md)). Exit 7 means the running Editor was unreachable. Waiting for the domain reload and retrying is sensible, though the docs don't promise it is retryable. Screenshots taken in batchmode need a real GPU and, according to a community thread rather than Unity staff, a full desktop session ([Unity Discussions](https://discussions.unity.com/t/capture-screenshots-in-batchmode/754535)). A logged-in Windows 11 desktop qualifies. Never pass `-nographics` for visual checks, and remember it also blocks GI baking ([Unity Manual](https://docs.unity3d.com/6000.3/Documentation/Manual/EditorCommandLineArguments.html)). Write a separate log file per run rather than reading the shared `Editor.log`. Unconfirmed: whether Pipeline screenshot and eval work in a pure batchmode Editor. Also treat the claim that a cold batchmode run cannot open a project already open in the warm Editor as practical experience rather than documented fact, and use a separate worktree for cold runs.

For multiplayer, **Multiplayer Play Mode 1.6 supports four editor players plus up to four local build instances, so a documented 8-instance local session is possible** ([Unity docs](https://docs.unity3d.com/Packages/com.unity.multiplayer.playmode@1.6/manual/index.html)). Play Mode Scenarios, which need Unity 6000.0.3f1+ and the Dedicated Server package, script mixed host, client and build setups ([requirements](https://docs.unity3d.com/Packages/com.unity.multiplayer.playmode@1.6/manual/play-mode-scenario/play-mode-scenario-req.html)). ParrelSync cannot be combined with MPPM, and Unity's samples have dropped it ([Meta docs](https://developers.meta.com/horizon/documentation/unity/unity-multiplayer-testing/)). Day to day, one host plus three virtual clients with bots in the remaining seats covers most cases. A headless all-bot soak build catches exceptions and stuck win conditions, and fixed seeds make every failure replayable. Before release, run a real Steam test with two or more accounts, because the Steam transport cannot be simulated inside MPPM. For CI, GameCI runs EditMode and PlayMode tests with a Personal license supplied as `UNITY_LICENSE`, `UNITY_EMAIL` and `UNITY_PASSWORD` secrets. Its default "All" mode does not include Standalone tests ([GameCI](https://game.ci/docs/github/test-runner/)). Some batchmode PlayMode runs hang in known edge cases ([GameCI issue](https://github.com/game-ci/unity-test-runner/issues/188)).

### One human sign-in, then everything is scriptable

**Unity Personal cannot be activated with serial numbers or command-line flags. It is activated by signing in to Unity Hub** ([Unity Manual](https://docs.unity3d.com/6000.4/Documentation/Manual/ManagingYourUnityLicense.html)). After that, batchmode runs use the license file at `C:\ProgramData\Unity\Unity_lic.ulf`, which is how GameCI runs Personal licenses. Check that the file exists, because Hub can show a license without having written it ([GameCI](https://game.ci/docs/github/activation/)). No documentation confirms that `unity license` can activate a Personal entitlement, so use Hub for this step.

## Conclusion

Unity's own roadmap has already made the engine, pipeline and tooling choices. The decisions that remain open are netcode physics, the 2027 NGO 3.0 migration, and license fine print. The most useful design principle to take from this research is to **make the game out of data, generators and seeds**. One representation then serves three consumers. The agent edits it as text. The network replicates it as a single number. QA replays it when a bot soak fails. Bots should be built before the fifth human seat. They fill empty lobbies, they put 8-player load on every local test session, and they are the only practical automated QA for a betrayal game whose failures emerge from interactions between players.

Because every agent-facing Unity tool is beta or experimental, build the agent workflow around the CLI's exit-code contract with plain batchmode as the fallback. If the Pipeline package or an MCP bridge changes or disappears, only the fast inner loop slows down; the verification gate keeps working. Three dates belong on the project calendar: the NGO-vs-FishNet physics proof of concept in the first two weeks, the move to 6.7 LTS with NGO 3.0 once that release has patches, and a pre-launch re-check of the FMOD, Photon and Unity MCP terms. Those are the places this research found pricing either in flux or contradicted by Unity's own pages.
